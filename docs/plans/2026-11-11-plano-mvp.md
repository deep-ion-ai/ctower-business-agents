## 1. Estratégia

Construir primeiro um **esqueleto de ponta a ponta** (uma pergunta ao sistema fictício, feita pelo Claude Code no terminal embutido, que vira documento na base) e depois alargar cada camada. Assim, cada parte nova já entra num fluxo que funciona e pode ser testado com o sistema fictício.

Ordem das camadas, de baixo para cima:

```
fundação ─► base de conhecimento ─► servidor MCP e ferramentas ─► integração com o Claude ─► interface
                 ▲                          ▲                              ▲
            mapeamento ─────────────────────┘                          prompts e fluxos
```

Princípios de execução:

- **Sistema fictício como gabarito desde o início** (#5). Toda ferramenta, prompt e tela é testada contra ele. Nenhum dado de sistema real entra no repositório.
- **Núcleo sem Tauri.** `cba-core` e as crates de baixo são testadas sem interface.
- **Recursos do Claude só documentados.** Links, configuração compartilhada e hooks ficam isolados em `cba-session` e cobertos por testes de fumaça (#42).
- **Versionado e distribuível desde o início.** SemVer com commits convencionais e `release-please` (#2); toda versão gera instaladores de Windows e macOS na GitHub Release (#3) e pode ser instalada por um comando (`curl` ou PowerShell) que também instala as dependências (#45). O instalador por script não dispara o aviso do navegador, então a assinatura (#41) fica para antes do piloto, começando pela opção gratuita para open-source (SignPath Foundation).
- **CLI primeiro, Desktop depois.** O terminal embutido é a experiência recomendada e a mais fácil de testar; o Desktop entra no M2.
